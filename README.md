# AI 模型路由网关（ai-auto-repety-gawaty）

多渠道多模型 AI 网关：分组多级容灾路由 + 三协议互转 + 成本统计 + 完整日志。

## 结构

- `server/` — Rust 网关（axum + reqwest + rusqlite），产出单文件 `gw-server.exe`（约 5MB）
- `client/` — Tauri 2 + Vue 3 桌面控制台，托管网关进程（sidecar）、开机自启（默认关）
- `docs/` — 设计与审查文档：[`方案.md`](docs/方案.md)（架构设计与实施进度）· [`loopguard-spec.md`](docs/loopguard-spec.md)（死循环拦截规格）· [`review/`](docs/review/)（技术选型 / 工程落地 / 事故复盘 三篇审查）

## 分组名即模型名

每个分组的**名称**和**id**本身就是一个可直接调用的模型名：用任意 OpenAI / Anthropic / Gemini 兼容客户端请求 `model: "<分组名>"`，网关就把该组所有层级的启用成员当成候选池，按层自动轮换与故障转移。

- **精确名优先**：如果请求的模型名正好出现在某个分组的 `exposed_models` 列表里，走的是窄语义（只调该模型绑定的候选），不会被同名分组截走
- `GET /v1/models` 同时列出 `exposed_models` 里的名字与各分组的名称/id
- 客户端「分组路由」页里每个分组都有一键复制的模型名提示
- 「渠道与模型」页可以从上游 `GET {base_url}/models` 拉取清单勾选导入，也可以手动填写（见下「添加模型」）

## 每个分组：跟随全局配置，或自己有配置

重试、超时、冷却等待、死循环拦截等预算默认继承全局（设置页的「默认重试与超时」）。在设置页的「分组配置」区，每个分组可以单独选择：

- **跟随全局配置**（默认）：改动全局值即时对该组生效
- **使用自己的配置**：该组用自己那份预算，可一键「复制全局配置」作为起点；服务端返回 `retry_source` 告知当前用的是哪一份

组级预算同样受 I4 约束（`max_attempts × attempt_deadline_ms + reserve_ms ≤ total_deadline_ms`），不合法的配置在保存时返回 400 且不会写入。

## 网关端口

| 面 | 端口 | 说明 |
|---|---|---|
| 数据面 HTTP | 8080 | `/v1/chat/completions` `/v1/messages` `/v1beta/models/{m}:generateContent` `/v1/models` `/healthz` |
| 数据面 HTTPS | 8443 | 同上，内置自签证书（localhost/127.0.0.1） |
| 管理面 | 127.0.0.1:9090 | `/admin/api/*`（config/logs/stats/health/test-channel/cooldown） |

## 快速开始（服务端裸跑）

```powershell
cd server
cargo build --release
$env:GW_DATA_DIR="D:/data"   # 目录或 gateway.db 文件路径
./target/release/gw-server.exe
```

配置持久化在 SQLite；首次启动用默认配置，之后通过管理面 PUT `/admin/api/config`（或客户端 UI）修改并热更新。

## 客户端开发

```powershell
cd client
pnpm install
pnpm tauri dev    # 桌面窗口 + 自动拉起网关
pnpm tauri build  # NSIS 安装包 + sidecar 打包
```

客户端 UI 页面：渠道（含透传 headers、连通测试=真实请求）、模型绑定（暴露名→上游名、四类价格，支持手动添加或从上游 models 接口勾选导入）、分组路由（一级/二级/… 成员顺序——拖动或按钮排序、与自动权重开关）、设置（重试/超时/监听/自启开关/自动权重/死循环拦截：检测到输出退化就丢弃该次尝试并在内部换下一个候选，代价是首字节推迟约 64 个字符——可配，且只覆盖回答开头）、日志（切换日志按 request_id 过滤 + 请求日志，退化尝试标记为「输出退化」）、统计（总览/按模型成本/冷却状态/死循环拦截次数）。

窗口会记住上次的大小与位置；开机自启默认关闭，开启后静默驻留托盘。

## 路由语义

- 分组内 tier 1 → 2 → … 升序尝试；同 tier 内**按列表顺序**依次尝试（默认）
- 自动权重（`auto_weight`，默认关闭）：开启后同 tier 内改为按成员权重降序，权重相同则保持列表顺序
- 「分组路由」页里成员的**顺序**和**权重**（数字输入框）在开关的两种状态下都能改：关闭时权重照常存盘但暂不参与调度，开启后立即生效，可以先批量填好权重再一次性开启
- 排序两种方式等价：按住成员行首的抓手**拖动**，或用**上移 / 下移**按钮（键盘与读屏可用）；层头的抓手可以拖动**层级先后**，拖到哪一级，层级号就跟到哪一级
- 候选失败 → 组内下一个；一级全冷却 → 下一级；末级也死 → 回到一级，循环 `max_cycles` 轮
- 全部冷却时 `cooldown_wait=true` 会等到最近一个冷却恢复再试（不白白失败）
- 健康 (channel × model) 粒度：401/403 整渠道隔离，404 只隔离该模型 6h，429/5xx 指数退避 15s→300s
- 提交点：流式请求在收到第一个合法内容帧后才向客户端写首字节（I1：提交前零字节），失败切换对客户端完全透明
- 中途断流：网关补 repair 帧（`gateway_upstream_interrupted`）+ 正常终止符，客户端永远拿到结构完整的响应

## 死循环输出拦截（loop guard）

模型陷入重复输出（死循环、无意义复读）时，网关在**内部**判为一次可重试的上游失败：丢弃这次尝试、按路由规则换下一个候选重试，客户端只看到一次正常回答、零字节外漏（默认开启）。

判定用滚动字符窗口上的 5 条规则（缓冲长度、重复次数、重复覆盖字符数、重复占比、单元不得是纯空白），阈值都在设置页可配。

**诚实边界（不要期待超出这些范围）**：

- 只有**流式**路径检测：`stream: false` 一次拿到完整 JSON，没有增量帧，不检测
- 只有**提交前**能内部重试：已经向客户端写出首字节之后再出现的退化无法内部换候选（换了就等于在同一条回答里塞第二次回答），这种情况沿用上面的 repair 帧语义，会带 `finish_reason=error`
- 开启后首字节推迟约 `min_chars` 个字符（默认 64，可配）；关掉它首字节立即返回，但退化不再被拦截
- 误判是可能的（长文里恰好出现高比例重复，例如连续空行或重复分隔线）；命中只影响该次尝试，会被内部重试吸收

## 添加模型：手动填写，或从上游 models 接口拉取

「渠道与模型」页的工具条和每张渠道卡片上都有**添加模型**入口，打开后是两种并列的方式：

- **手动添加**：自己填绑定 ID、暴露模型名、上游模型名，并选一个渠道（也能顺手改四类价格）
- **从 models 接口获取**：选渠道 → 点「获取模型列表」，网关用该渠道的 `base_url` + API Key 去请求上游 `GET {base_url}/models`，把返回的模型名列成清单，勾选后一键导入（暴露名 = 上游名，之后可再逐条改）

细节与边界：

- 拉取走服务端 `POST /admin/api/channel-models`，浏览器不直接碰上游；也支持只给草稿 `base_url` + `api_key`（渠道还没保存进配置时就能先探一次）
- 已在本渠道绑定过的上游模型显示「已存在」并不可勾选，不会重复导入
- 上游返回的模型列表带 `latency_ms`；清单过长会截断（响应里有 `truncated`）
- 失败一律可见地报在弹窗状态区（例如密钥错就是 `HTTP 401`），**不会**假装成功返回空列表
- 整段请求（连响应体）共用一个 20 秒超时，上游先回响应头再挂住 body 也不会让弹窗一直转圈
